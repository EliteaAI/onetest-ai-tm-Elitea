# ELITEA-0998: Pyodide Sandbox (pyodide_sandbox) Intercepted — Arbitrary Code Execution Guardrail

**Module:** Sensitive Tool Calling · **Priority:** High · **Type:** Functional

**Objective:** Verify that the authorization guardrail intercepts the pyodide_sandbox (or python_code_sandbox) tool — which executes arbitrary Python code in a Deno/WebAssembly sandbox — before any code runs, and that Block fully prevents code execution with no side effects.

## Preconditions

- pyodide > pyodide_sandbox (or pyodide > python_code_sandbox) is configured as sensitive in Admin UI → Configuration → Guardrails
- An agent configured to use the Pyodide sandbox tool is available
- Services restarted after configuration save

## Test Data

- Sensitive tool: pyodide.pyodide_sandbox
- Agent prompt: 'Write and run Python code to calculate the first 10 Fibonacci numbers'
- Expected parameter in dialog: code: 'def fib(n): ...' (Python code generated by the agent)
- Note: 'code' is NOT a sensitive field name and must NOT be masked

## Steps

| # | Action | Expected Result |
|---|--------|----------------|
| 1 | Navigate to Admin UI → Configuration → Guardrails. Enable pyodide > pyodide_sandbox (or python_code_sandbox) as sensitive. Save and restart services. | Configuration saved successfully. |
| 2 | Open the agent with the Pyodide sandbox tool configured. Send the prompt: 'Write and run Python code to calculate the first 10 Fibonacci numbers'. | Agent begins generating code. |
| 3 | Observe the chat area before any code runs in the Deno subprocess. | Authorization dialog appears with title '⚠️ Sensitive Action Authorization Required'. No Deno process has been spawned yet. |
| 4 | Verify the dialog shows action name pyodide.pyodide_sandbox or pyodide.python_code_sandbox. | Correct tool identifier is displayed prominently. |
| 5 | Verify the Parameters section shows the code field containing the full Python code the agent intends to execute. | The code parameter value is the Python source code generated by the agent, displayed in full (not masked — code is not a sensitive field name). |
| 6 | Click [Authorize]. | Dialog closes. The Python code is submitted to the Deno/Pyodide subprocess. Agent returns the execution output (e.g., Fibonacci sequence result). |
| 7 | Trigger the same prompt again. When the dialog appears, click [Block]. | Dialog closes. The Deno subprocess is NOT spawned. No code executes. Agent acknowledges the block. |
| 8 | Verify no subprocess side effects occurred after Block: no files written, no network calls made. | No unexpected side effects. Execution time result is not returned. Agent response confirms blockage. |
| 9 | Verify the code parameter value is NOT masked (it is not a secret field name). | The Python code content is displayed in full in the Parameters section — not redacted as ***. |

## Expected Final State

The Python code content is displayed in full in the Parameters section — not redacted as ***.

## Pass/Fail Criteria

Pass:
- Authorization dialog appears before the Deno subprocess starts
- code parameter is displayed in full (not masked \u2014 it is not a secret field)
- Authorize: Deno runs the code and agent returns proper output
- Block: no Deno subprocess spawned, no side effects, agent acknowledges
- Tool name (pyodide_sandbox / python_code_sandbox) is correctly shown in dialog

Fail:
- Python code executes in the sandbox before any dialog is shown
- Dialog appears after code execution (side effects already happened)
- code parameter is incorrectly masked as ***
- Block does not prevent subprocess execution
