# ELITEA-3046: Additional Header Values Are Never Exposed in Plaintext via API Read or Application Logs

**Module:** Toolkits & Credentials / OpenAPI Toolkit Secret Headers · **Priority:** High · **Type:** Security

**Objective:** Confirm additional header values are never exposed in plaintext through any read path, consistent with how `api_key`/`client_secret` are already masked. GET the credential/toolkit settings via the API and confirm header values come back masked. Additionally, check application logs after a tool execution to confirm header values are not logged in cleartext — the Rust replatform worker explicitly marks these header values `sensitive` before use; verify the primary `elitea-sdk`/legacy backend gives the equivalent guarantee.

---

## Preconditions

- An OpenAPI credential with at least one additional header configured with a known, identifiable value (e.g. `X-Api-Key: super-secret-marker-value`).
- API access to GET the credential/configuration resource directly.
- Access to application/backend logs generated during a tool execution using this credential (or an equivalent way to confirm log content, if direct log access isn't available).

---

## Test Data

| Field | Value |
|-------|-------|
| Additional header | `X-Api-Key: super-secret-marker-value` |

---

## Steps

| # | Action | Expected Result |
|---|--------|------------------|
| 1 | Save the credential with the header above. | Save succeeds. |
| 2 | GET the credential/configuration resource via the API. | The header value in the response is masked (e.g. redacted/placeholder), not `super-secret-marker-value` in plaintext. |
| 3 | Trigger a tool call through the toolkit built on this credential. | Tool call executes using the real header value. |
| 4 | Search application/backend logs generated by this call for the literal string `super-secret-marker-value`. | The literal value does not appear anywhere in logs — confirming it's treated as sensitive, not just masked in the UI/API response. |

---

## Expected Final State

The additional header value is masked in every read path (API and UI) and never appears in plaintext in application logs.

---

## Pass/Fail Criteria

**Pass:** The header value is masked in the API GET response and does not appear in cleartext in any log output from the tool execution.
**Fail:** The API GET response returns the header value in plaintext, or the literal value appears unmasked in application logs.
