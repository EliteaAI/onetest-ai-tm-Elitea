# ELITEA-0882: Webhook Trigger — Configuration Persistence and YAML Exclusion

**Module:** Entrypoint Trigger Type · **Priority:** Medium · **Type:** Functional

**Objective:** Verifies that Webhook configuration (type) persists correctly after save and reload, that the config is stored in the DB (verifiable via GET trigger API), that Webhook config does NOT appear in the YAML, and that the Webhook settings modal shows the Payload Format section with curl example.

## Preconditions

User is logged in with pipeline edit permissions
A pipeline with a Webhook trigger configured (type: Custom) is saved — secret is auto-generated by the system
Access to GET trigger API endpoint

## Test Data

API endpoint: GET .../pipeline_trigger/prompt_lib/{project_id}/pipeline/{pipeline_id}/trigger
Secret: auto-generated by system — copy from the UI Webhook config after saving

## Steps

| # | Action | Expected Result |
|---|--------|----------------|
| 1 | Configure Webhook trigger with type 'Custom' and save — note and copy the auto-generated secret value displayed in the UI | Pipeline saves successfully |
| 2 | Reload the page and open the Entrypoint node Webhook config | Webhook Type is still 'Custom'; Secret Value field is populated (auto-generated value; may be masked) |
| 3 | Call the GET trigger API for this pipeline | API response returns correct trigger type (webhook/custom) and confirms the secret is stored; response does NOT indicate the trigger is Chat Message or Schedule |
| 4 | Open the pipeline's YAML view and search for webhook-related fields | No webhook trigger fields appear in the YAML — YAML is clean of webhook config |
| 5 | Open the Webhook settings modal/configuration panel | A Payload Format section is visible confirming that the raw request body is passed as user input |
| 6 | Observe the example Request section in the modal | An example curl command is shown reflecting the correct Webhook URL and the appropriate auth header for Custom type (X-Webhook-Token) |
| 7 | Switch type to GitHub and observe the example curl | The example curl shows X-Hub-Signature-256 header and an HMAC computation hint |

## Expected Final State

The example curl shows X-Hub-Signature-256 header and an HMAC computation hint

## Pass/Fail Criteria

PASS: Config persists; API confirms correct values; YAML clean of webhook fields; Payload Format section present; curl example correct per type
FAIL: Config lost on reload; API returns wrong values; YAML contains webhook fields; modal missing Payload Format; curl example wrong
