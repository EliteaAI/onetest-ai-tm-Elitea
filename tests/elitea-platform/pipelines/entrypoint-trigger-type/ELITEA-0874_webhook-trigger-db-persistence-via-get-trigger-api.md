# ELITEA-0874: Webhook Trigger — DB Persistence via GET Trigger API

**Module:** Entrypoint Trigger Type · **Priority:** Medium · **Type:** Functional

**Objective:** Verifies that the Webhook trigger configuration (type and secret reference) is stored in the database and accessible via the GET trigger API endpoint, and that the API returns correct values after save.

## Preconditions

User is logged in with API access
A pipeline with a Webhook trigger (Custom type) has been configured and saved
Access to: GET .../pipeline_trigger/prompt_lib/{project_id}/pipeline/{pipeline_id}/trigger

## Test Data

Pipeline ID and project ID: obtain from the pipeline URL
Webhook type: Custom
Secret: auto-generated by system (copy from UI after saving)

## Steps

| # | Action | Expected Result |
|---|--------|----------------|
| 1 | Configure the pipeline's Entrypoint with Webhook trigger (Custom type) and save — note the secret is auto-generated; observe and note the value displayed in the UI | Pipeline saved |
| 2 | Call GET .../pipeline_trigger/prompt_lib/{project_id}/pipeline/{pipeline_id}/trigger | API returns HTTP 200 |
| 3 | Inspect the response body | Response contains the correct trigger type (webhook/custom) and a reference or confirmation that the secret was saved; no Chat Message or Schedule is returned as the type |
| 4 | Change the webhook type to GitHub and save | Pipeline saves |
| 5 | Call the GET trigger API again | Response confirms trigger type is now GitHub webhook |

## Expected Final State

Response confirms trigger type is now GitHub webhook

## Pass/Fail Criteria

PASS: GET API returns correct type and secret reference; updates reflected after type change
FAIL: GET API returns wrong type; secret not stored; API returns 404 or 500
